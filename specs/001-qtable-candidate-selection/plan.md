# Implementation Plan: Q-Table Candidate Selection for 3L-Cache

**Branch**: `rl-candidate-selection` | **Date**: 2026-06-30 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-qtable-candidate-selection/spec.md`

## Summary

Add `TLCacheQL`, a new cache variant that inherits all behavior from `TLCache::TLCacheCache` and overrides only the `rank()` method — the heuristic candidate-selection stage. `rank()` is replaced by a tabular Q-learning policy that scans the cache queue and uses a discretized (frequency, age, size) state to decide which objects to nominate as eviction candidates. The inherited GBM reuse-time predictor (`prediction()`) remains in the eviction path to rank the Q-table-selected candidates. A `lookup()` override detects re-requests of recently evicted objects via the existing `out_cache` history window and uses them as the reward signal to update the Q-table online.

**Language/Version**: C++17 (core), Python 3 (evaluation scripts)

**Primary Dependencies**: LightGBM (`LightGBM/c_api.h`) — inherited; libCacheSim C ABI (`cache_t` function-pointer interface)

**Storage**: In-process only; `unordered_map` for Q-table and pending-reward tracking. No files.

**Testing**: `miss_ratio_boxplot.py`, `cpu_overhead_boxplot.py`, `cachesim` binary (libCacheSim evaluation harness)

**Target Platform**: Docker (Ubuntu 18.04, cmake 3.28.6) — per constitution

**Project Type**: Research library / cache-simulation variant

**Performance Goals**: CPU overhead within 3L-Cache's documented low-overhead threshold relative to LRU (constitution principle II)

**Constraints**: Q-table must remain ≤ 512 entries; `unordered_map` lookup added per candidate scan step must be < 10 ns; total state space encoded in 9 bits (uint32_t)

**Scale/Scope**: One new `.h`, one new `.cpp`, one new `_Interface.cpp`; one line added to each evaluation script

## Implementation Design

### `TLCacheQL.h` — class skeleton

```cpp
namespace TLCacheQL {

struct PendingUpdate {
    uint32_t state;   // QState at eviction time
    uint8_t  action;  // always 1 (nominate)
};

class TLCacheQLCache : public TLCache::TLCacheCache {
public:
    unordered_map<uint32_t, array<float,2>> q_table;   // state -> [q_skip, q_nominate]
    unordered_map<uint64_t, PendingUpdate>  pending_updates;
    float    q_alpha   = 0.1f;
    float    q_epsilon = 0.1f;
    uint64_t q_table_updates = 0;

    void init_with_params(const map<string,string>& params) override;
    bool lookup(const SimpleRequest& req) override;
    uint32_t rank() override;
    void update_stat_periodic() override;

private:
    uint32_t encode_state(const Meta& meta) const;
    void apply_reward(uint64_t key, float reward);
};

} // namespace TLCacheQL
```

### `rank()` override — logic outline

```
1. Cold-start guard: if (!booster) -> call base TLCacheCache::rank() and return.
2. quick_demotion() -> same as base (inherited).
3. Q-table scanning (replaces the freq-boundary heuristic loop):
   a. Walk cache queue from samplepointer for up to sample_rate steps.
   b. For each object:
      - Compute encode_state(meta) -> s
      - Look up q_table[s]; default {0,0} if missing
      - epsilon-greedy: with prob epsilon choose random action; else choose higher Q-value action
      - If action = nominate -> add pos to sampled_objects
   c. Advance samplepointer; wrap around as in base rank().
   d. Ensure sampled_objects.size() >= eviction_rate (force-nominate LRU head if empty).
4. prediction(sampled_objects) -> inherited unchanged.
5. Return sampled_objects.size().
```

### `lookup()` override — reward detection

```
1. Call base TLCacheCache::lookup(req).
2. If the object was found in out_cache (re-request of evicted object):
   - Check pending_updates[req.id]; if present -> apply_reward(req.id, -1.0f).
3. Return base result.
```

### `apply_reward(key, r)` — Q-update

```
1. Find pending_updates[key] -> {state, action}.
2. old_q = q_table[state][action]  (default 0 if missing)
3. q_table[state][action] = (1 - q_alpha) * old_q + q_alpha * r
4. q_table_updates++
5. Erase pending_updates[key].
```

### Out-cache age-out — positive reward

`erase_out_cache()` removes old entries from `out_cache`. Override (or hook into `admit()`) to apply `+1` to any `pending_updates` entry whose key is being dropped from `out_cache` without having triggered a negative reward.
